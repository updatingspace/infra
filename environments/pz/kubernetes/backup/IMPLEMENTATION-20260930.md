# Внедрение backup: 30 сентября 2026

**Внедрение продолжается: первая копия опубликована с полным S3 readback и
COMMITTED. Независимый полный restore drill прошёл все семь проверок.
Перенос игровых данных на SSD остановлен лимитом времени при итоговой проверке.
Cutover не выполнен; приложения возвращены на исходный диск, копия SSD сохранена.
Регулярные таймеры и retention выключены до исправной
cleanup и проверки backup после переноса.**

Согласованы раздельные S3 credentials, закрытое операторское хранение с правами
0600, окна обслуживания, ежедневный запуск в 06:00 МСК и мониторинг в Monium.
Приватный age-ключ и restore credentials хранятся вне игровой VM; для шифрования
на VM передан только public recipient. Этот отчёт не содержит идентификаторов
облачных ресурсов, адресов VM, production-настроек и путей приватного хранилища.

| --- | --- |

| Backup runtime | Первый capture завершён, приложения восстановлены; S3 COMMITTED подтверждён полным readback |
| Независимый restore | Полное восстановление и изолированный запуск прошли все семь проверок; подлинная аттестация связана с проверенным COMMITTED |
| Upload retry | Пустая очередь пропускается до запуска цепочки cleanup/retention; лишних полных чтений S3 каждые десять минут нет |

Состояния Terraform и инструкции восстановления сохраняются отдельно от
регулярной ротации игровых копий. Подготовлен предварительный зашифрованный
операторский control bundle: потоковая расшифровка и SHA256 включённых файлов
проверены без открытых временных файлов. Приватный age-ключ и три S3-ключа в него
не включены. Финальный набор будет пересобран после завершения миграции и
включения расписания; в S3 этот отдельный набор не загружался.

проверенному для этого внедрения, два новых диска стоят **до 820,78 ₽ за 31 день**:
SSD 592,22 ₽ + HDD 228,56 ₽. Они оплачиваются с момента создания; существующая
VM в этот расчёт не входит.

Фактический размер первого зашифрованного комплекта и оценка пяти копий
зафиксированы в закрытом операторском отчёте. Помимо хранения нужно учитывать проверочные чтения,
операции и применимый исходящий трафик по
[тарифу Object Storage](https://yandex.cloud/ru/docs/storage/pricing#prices).
Размер мира сам по себе не определяет размер восстановимого комплекта: в него
также входят нужные версии binaries, модов, панели и конфигураций.

  временные объекты и multipart убраны. Для GET отсутствующего объекта вне

  **29 verify-live fixtures**. Проверки охватывают

  отдельно от ещё не применённого расширения прав cleanup.

  Полные отчёты и измерения RTO сохранены в закрытом операторском хранилище.

## Найденные проблемы

При настройке устранены ограничения квоты и особенности Object Storage:
не требующийся новому bucket versioning PUT убран, управляющие права ограничены
перечнем операций. Для conditional multipart SDK подписывает If-None-Match
при создании загрузки и передаче частей; список multipart разрешён на конкретный
bucket без неподдерживаемого prefix context. Повторная canary прошла.

Проверка чистого завершения учитывает, что containerd может опускать protobuf
поле `exit_status` при нулевом значении. Она связывает исходный контейнер,
событие завершения и отсутствие его процессов; исчезновения pod недостаточно.
Поведение подтверждено отдельной проверкой и покрыто тестами.

Ранний capture прерван после оценки длительности копирования. Проверенная
staging-копия остаётся обязательной до возвращения writers, а путь упаковки
оптимизирован для уменьшения числа отдельных операций на диске. Повторный
capture завершился успешно, содержимое и manifest полностью перечитаны из S3.

Окно восстановления превысило план из-за несовместимого автоматического
обновления Storm. Предыдущую совместимую версию восстановили, точный локальный
runtime pin закрепили и защитили от перезаписи при синхронизации secrets.
Игра восстановила health без принудительного завершения игрового процесса.

Первый изолированный запуск выявил ошибку offline-адаптации модов: symlinks
создавали расхождение между canonical и lexical путями загрузчика. Harness
использует проверенные nested bind mounts и явно заданный canonical cache
directory. После нового полного извлечения повторный drill успешно загрузил
сохранённый мир и ожидаемые моды. Production-конфигурация для этого не менялась;
evidence неудачной попытки сохранено отдельно.

Для полного извлечения добавлен opt-in режим checked filesystem-syncfs:
дескриптор доверенного родительского каталога открывается до записи, полный
поток и извлечённое дерево проверяются, затем проверяется результат syncfs.
Ошибка барьера не допускает успешного отчёта. SHA и metadata проверки сохранены;
режим по умолчанию с fsync каждого файла не изменён.

Полное source hashing, rsync и сверка target не уложились в исходный бюджет.
Helper вернул исходную файловую систему в RW и восстановил приложения до
изменения fstab или boot guard; непроверенный SSD не активирован. Подготовлено
явное продолжение с сохранением старого journal и повторным использованием
частичного target только как кеша. Временный пониженный резерв свободного
места возвращён к исходному, exporter включён при загрузке.

## Что остаётся выполнить

1. После проверки здоровья согласовать более длинное окно и выполнить явный
   resume с новым source SHA и полным сравнением target. Подтвердить UUID mount,
   boot guard и здоровье после cutover; сохранить старое хранилище для отката.
2. Завершить исправление cleanup, выполнить первый проверенный backup после
   переноса и согласовать IaC states. До этих gates таймеры и retention выключены.
3. Включить ежедневные 06:00 МСК и upload/retry timers вместе с retention только
   после подтверждения всех gates; проверить расписание и запас места.
4. Пересобрать операторский control bundle с сохранёнными restore evidence.
   Проверить естественное накопление
   пяти успешных игровых комплектов отдельными запусками.
