# Метрики игрового контейнера в панели

Применено 30 сентября 2026 через Terraform. Проверены HTTP health, новые карточки
в авторизованном браузере, 10 разрешающих/запрещающих RBAC-запросов и no-op план.
Наблюдатель подтвердил прежний игровой процесс и 0 рестартов; hourly updater включён.

Адаптер заменяет HOST-карточки главной страницы показателями конкретного
`zomboid/zomboid-0`, привязанного к профилю панели
`806c8584-0e2b-4c53-a255-3c244cde82ba`. Он не меняет лимиты и не перезапускает игру.
Лимиты уже применяются cgroup: игра 2.2 CPU / 10 GiB, панель 0.3 CPU / 768 MiB.
Общие `os.cpus()/totalmem()/freemem()` не отражают эти контейнерные ограничения.

| Карточка | Источник и смысл |
|---|---|
| Game CPU | Metrics API, использованные CPU относительно действующего CPU limit игрового контейнера; лимит виден в подсказке |
| Game RAM | Working set из Metrics API / действующий memory limit; это не полное `memory.current` с учётом всего файлового кэша |
| JVM heap | Сумма `jvm_memory_used_bytes{area="heap"}` / определённые `jvm_memory_max_bytes{area="heap"}` из экспортера игры |
| Disk | Прежний замер файловой системы сохранений; её размер меняется отдельной процедурой |

HOST swap скрыт: данных swap конкретного контейнера этот адаптер не собирает.
Системная диагностика в других разделах upstream-панели не переписывается;
адаптер меняет главную страницу и её историю. Это исправление отображения,
а не дополнительная граница безопасности ядра.

## Ограничения доступа

ServiceAccount `panel-telemetry` может только GET одного core Pod и одного
metrics Pod с именем `zomboid-0` в namespace `zomboid`. Нет list, Secret API,
exec или операций изменения. Токен читает только серверный код, перечитывая
его при каждом запросе; HTTPS использует CA Kubernetes. При обращении к
внутреннему игровому экспортеру этот токен не передаётся.

Дополнительный egress разрешает только Kubernetes Service IP:443 и фактический
API endpoint:6443. Доступ к metadata и прочим частным адресам не добавляется.
Код адаптера смонтирован из ConfigMap только для чтения. Хостовые PID, proc,
cgroup или Docker socket в панель не монтируются.

## Достоверность показаний

Проверяются имя/namespace/владелец pod, Ready контейнера, его фактические limits,
возраст метрик и полное окно измерения после старта контейнера. Повторный Pod GET
должен подтвердить прежние UID, container ID и время старта. При ошибке,
просроченных данных, остановленной игре или другом активном профиле новая точка
не записывается: нет подстановки хостовых чисел или нулей.

Новые записи помечаются `telemetryScope=game-container-v1`. Старые HOST-записи
не удаляются адаптером, но исключаются из выдаваемой истории и нового графика;
обычный upstream retention продолжает действовать. Heap JVM не заменяется
памятью процесса панели. Метрики обновляются штатным опросом панели раз в минуту.

## Совместимость и автообновления

Используется официальный образ панели без отдельной сборки. `NODE_OPTIONS`
подключает `preload.mjs`. Документированные Node.js loader hooks преобразуют
только проверенные участки серверного кода в памяти. Клиентский адаптер создаёт
новые копии JS с отдельными URL, переписывает весь граф импортов и переключает
`index.html` последним. Старый семидневный браузерный кэш не подменяет новый UI;
исходные JS и `build-info.json` сохраняются.

Каждый узел преобразования проверяется строгими признаками структуры. При
несовместимой будущей версии запуск завершается до HTTP readiness. Updater
дополнительно требует `/api/health.telemetry` с полями `adapter`, `compatibility`
и `scope`; при отказе кандидата до переключения трафика действует его штатный
откат образа и данных. Любая будущая версия не считается совместимой заранее.
`telemetry.ready=false` из-за остановленной игры не запрещает обновление панели.

В `/api/health` также доступны свежесть и действующие лимиты без credentials.
Для приёмки работающей игры нужны `telemetry.ready=true`, значения 2.2 / 10 GiB
и фактические виджеты в браузере. Базовый health не заменяет такую приёмку.

Применять через защищённый `deploy.py plan workloads` / `apply workloads`:
updater приостанавливается и проверяется его завершённый журнал. Terraform
сначала создаёт доступ на чтение, затем штатно пересоздаёт только панель.
Для отката адаптера установить `panel_telemetry_enabled=false` в приватных
workloads variables и применить просмотренный план тем же helper. Это вернёт
upstream-виджеты; игровые данные и образ остаются прежними.

Проверки без кластера:

```sh
node environments/pz/kubernetes/panel-telemetry/test-provider.mjs
node environments/pz/kubernetes/panel-telemetry/test-server-transform.mjs
node environments/pz/kubernetes/panel-telemetry/client-overlay.test.mjs
```
